# Technical debt register

Known shortcuts, fragilities and deferred work. One row per item; an item is
closed by moving it to **Closed** with the commit or ADR that resolved it, not by
deleting it. Decisions behind the items are in [`adr/`](adr/README.md).

**Priority** — P1: can show wrong data or lock people out. P2: will need a
developer when a foreseeable event happens. P3: cleanliness.

Last reviewed: 2026-09-30.

## Open

| ID | P | Area | What | Why it matters | Way out |
|---|---|---|---|---|---|
| TD-01 | P2 | Escolar ingest | Per-course planillas come from a static index (`src/data/escolarPlanillaIndex.json`, parsed from `docs/Planillas PAF Escolar.xlsx`). | A new school loads only the indicators of Datos Consultor / Registro Coordinación until a developer regenerates the index and redeploys functions. The email lists it as "falta: planillas por curso". | Register per-course planillas from the admin screen; the ingest merges the index with what is stored on the establishment. Agreed as next delivery. |
| TD-02 | P2 | Ingests | Cohort sources are constants: `SCHOOL_FOLDERS` in `ingestEscolar.mjs`, `CENTRALES` / `BASES_SCJI` in `ingestParvulario.mjs`, `COHORTES` in `src/lib/registro.js`, year 2026 in `scope.js`. | Cohort 2027 requires code changes in several files. | Move sources to `config/` and edit them from the admin screen. To be scoped after this delivery. |
| TD-03 | P2 | Coverage | The Escolar coverage manifest is generated by hand and shipped in the frontend bundle. | A new school has no coverage states until the manifest is regenerated and hosting redeployed. | Generate it in the pipeline and read it from Firestore. |
| TD-04 | P1 | Escolar ingest | A tab that fails to read is logged and skipped; with `--prune`, the values it would have produced are then marked "sin dato". Confirmed by reading the code, not observed in production. | A transient Sheets or permission error blanks part of a school for one day (the previous value is kept in `valorAnterior` and the next good load restores it). | Track which sources were read successfully and prune only within those. |
| TD-05 | P2 | Pipeline | Escolar read errors are detected by matching text in the script's output (`runPipeline.mjs → resumir`). | A change in a log message silently disables the warning. | Have the ingest write read errors to its JSON report. |
| TD-06 | P3 | Rules | `config/*` is publicly readable, including `pipelineMetadata` (step errors, establishment names with pending data). | Low sensitivity, but more than an anonymous visitor needs. | Public read only for `config/dataSource`; the rest for valid users. |
| TD-07 | P3 | Data | 18 Escolar docs in `resultados_real` have no `periodo`. | Left over from an older id format; ignored by the views, noise in audits. | Identify their origin and mark or remove them with a reported migration. |
| TD-08 | P2 | Auth | Login is Google-only, but "Crear usuario" asks for a password. | The password is never used: the account only pre-assigns a profile to an email that later signs in with Google. Confusing for the administrator. | Drop the password field (create the account without one), or add email/password sign-in. Needs a product decision. |
| TD-09 | P3 | Auth | The superadmin whitelist is duplicated in `src/lib/firebase.js` and `firestore.rules`. | The two lists can drift. | Keep it in one place (`config/` read by both, or custom claims). |
| TD-10 | P3 | Auth | "Ver como" works by the superadmin overwriting `slepId` / `establecimientoId` on their own `usuarios` doc. | View state stored as identity data; two tabs interfere with each other. | Keep the viewed entity in client state only; superadmin rules already allow every read. |
| TD-11 | P2 | Operations | The status email is sent through a personal Gmail account with an app password; the Cloud Monitoring alert has a single recipient. | If that account or its app password changes, the daily email stops (the run itself is unaffected). | Transactional email provider or a project mailbox; add a second alert recipient. |
| TD-12 | P3 | Pipeline | Fixed universe assumptions remain: "de 51 indicadores" in the email, "universe ≥ 18" for the fallback tier in `computeTerritorioAggregates.mjs`. | Wrong text or a weaker privacy argument if the universe shrinks. | Derive from the catalog / check the count at run time. |
| TD-13 | P2 | Data | RBD values have inconsistent lengths in `establecimientos_real` (5 and 7 digits). | Some are probably not RBDs. Shown in the admin screen. | Confirm with Focus and correct from the admin screen. |
| TD-14 | P2 | Quality | The only automated checks are `npm run test:reglas` and the color-token guard, run by hand. No CI. | Regressions in rules, ingests or aggregation are caught by people. | CI job: build, rules test on emulators, unit tests for `scope.js` and `registro.js`. |
| TD-15 | P3 | Repo | One-shot and superseded scripts are still in `scripts/` (`backfillSlepOnResultados`, `backfillSlepIdOnUsuarios`, `syncPlanillasCentrales`, `migrateCanonicalIndicadorIds`, `seed`, `enrichEstablecimientos`…), and `firestore.rules` still has blocks for collections nothing reads (`/establecimientos`, `/valores`, `/sostenedores`, …). | Someone may run the wrong script; rules are harder to audit. | Move to `scripts/archive/`; remove dead rule blocks. |
| TD-17 | P2 | Runtime | Functions run on Node 20 (`functions/package.json`), which reached upstream end of life in April 2026. | Deploys will be refused once Cloud Functions decommissions the runtime. | Check the decommission date and move to Node 22. |
| TD-18 | P2 | Dependencies | Root and `functions/` pin different majors of the libraries the pipeline uses (`firebase-admin` 14 vs 13, `googleapis` 173 vs 144). | The pipeline is tried locally with one set of libraries and runs nightly with another. | Align both `package.json` files. |
| TD-19 | P2 | Ingests | `ingestRosterEscolar.mjs` (manual) writes `nNinos`, `nAgentes`, `rbd` without honouring `camposPlataforma`. | Running it would overwrite data edited in the platform (ADR-0002). | Route its writes through `respetarPlataforma`, or retire it once the admin screen is the source. |
| TD-20 | P3 | Frontend | The main bundle is over 500 kB minified. | Slower first load. | Code-split the admin and comparator views. |
| TD-21 | P3 | Aggregates | `aggregatesTerritorio_real` is recomputed only at night. | After a sostenedor change, peer averages are stale until the next run. | Recompute the affected SLEPs from the admin function. |
| TD-22 | P3 | Registry | A platform-edited field cannot be handed back to the planilla, and there is no history of who changed what beyond `editadoPor`. | Corrections of a wrong edit need a second edit; no audit trail. | "Volver a la planilla" action; append-only change log. |
